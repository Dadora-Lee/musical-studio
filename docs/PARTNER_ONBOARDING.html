🤝 Musical Studio · Partner 합류 가이드

당신은 공동 개발자입니다. AI Agent를 함께 활용해서 자동으로 셋업합니다. 본 가이드는 AI가 못하는 4가지를 안내합니다.

당신이 직접 해야 할 일 (1회, ~20분)

  1. GitHub Fine-grained PAT 발급
  2. SSH key 등록 (시크릿 받기용)
  3. 본인 PC 사전 도구 설치
  4. AI Agent에 프롬프트 입력
  5. 결과 확인 + 진행
중요: 본 가이드는 당신이 직접 해야 할 일만 다룹니다. 이후 모든 셋업 (clone, gh 인증, secrets 받기, 의존성 설치, 테스트, 첫 PR)은 AI Agent가 자동 진행합니다.

Step 1. GitHub Fine-grained PAT 발급

1왜 필요한가

당신의 AI Agent가 GitHub에 commit/push할 때 본인 계정으로 인증해야 합니다. SSH는 별도(2단계). PAT는 HTTPS 인증용.

2발급 절차

  1. github.com/settings/personal-access-tokens 접속
  2. Generate new token (Fine-grained) 클릭
  3. 설정:
    • Token name: musical-studio-partner
    • Expiration: 90 days (또는 정책에 맞게)
    • Repository access: Only select repositories → Dadora-Lee/musical-studio
    • Permissions:
      • Contents: Read and write
      • Pull requests: Read and write
      • Issues: Read and write
      • Metadata: Read-only (자동)
  4. Generate token → 표시되는 github_pat_... 즉시 복사 (다시 볼 수 없음)
  5. 임시 안전한 곳에 보관 (Bitwarden 추천). Step 4에서 사용.

Step 2. SSH key 등록

1왜 필요한가

Owner의 dev server에서 시크릿(.env/secrets.env)을 SCP로 안전하게 받습니다. 본인 SSH 공개키가 github.com에 등록되어 있어야 owner가 자동으로 인증 등록해줄 수 있습니다 (이미 처리됨).

2SSH key 생성 (이미 있으면 SKIP)

본인 PC의 터미널 (Windows는 Git Bash 또는 WSL, macOS/Linux 기본 터미널):

# 기존 키 확인
ls ~/.ssh/id_ed25519.pub 2>/dev/null && echo "있음" || echo "없음"

# 없으면 새로 생성
ssh-keygen -t ed25519 -C "your-email@example.com"
# 모두 Enter (기본 경로 + 빈 passphrase 또는 본인 passphrase)

3GitHub에 등록

  1. 공개키 복사: cat ~/.ssh/id_ed25519.pub 출력 전체 복사 (ssh-ed25519 ...로 시작)
  2. github.com/settings/ssh/new 접속
  3. Title: musical-studio-partner
  4. Key: 붙여넣기
  5. Add SSH key

4등록 확인

curl https://github.com/<your-username>.keys

본인 공개키가 출력되면 OK. Owner는 이걸 보고 인증 등록을 자동 처리합니다.

Step 5. 결과 확인

1AI 진행 모니터링

AI Agent가 다음을 자동으로 합니다:

  • gh CLI 인증 (HTTPS + PAT)
  • repo clone (WSL ext4 또는 ~/projects/)
  • 기존 작업물 통합 (있을 시) — 새 branch + draft PR
  • SSH SCP로 시크릿 받기
  • pnpm install + .env.local 자동 생성
  • typecheck/lint/test 검증
  • dev server 실행 확인

2막힐 수 있는 부분

다음 경우 AI가 멈추고 당신에게 물어볼 수 있습니다:

  • SSH 연결 실패 — Owner에게 "내 GitHub username 보내드렸으니 ssh-import-id 했는지 확인 부탁" 요청
  • 기존 작업물 통합 시 코드 충돌 — 당신의 의도 확인 필요
  • PAT 권한 부족 — Step 1의 권한 다시 확인 (Contents/PR/Issues: RW)

FAQ

Q. PAT를 채팅창에 입력해도 안전한가요?

Claude Code, Antigravity, Codex CLI 같은 정식 AI Agent는 PAT를 메모리에만 두고 파일로 저장하지 않습니다. 하지만 보안을 더 높이려면 AI에 빈 값으로 보내고 본인이 직접 gh auth login --with-token을 실행하는 것도 가능합니다.

Q. Dev server에 SCP가 안 돼요

Owner에게 다음 2가지 확인 요청:

  1. 본인 GitHub username 알려주고 bash scripts/partner-onboard.sh <your-username> 실행했는지
  2. SSH 서버 + 공유기 2222 포트포워딩 활성화됐는지

대안: Owner가 Bitwarden/1Password로 .env/secrets.env 텍스트 직접 공유.

Q. AI Agent가 "기존 작업물 위치" 묻는데 잘 모르겠어요

혹시 다른 곳에서 musical-studio 관련해서 코드 작성한 적 있나요? 없으면 "없음"으로 답하세요. 있는데 어디인지 모르겠으면 find ~ -name "musical-studio" -type d 2>/dev/null 명령으로 찾을 수 있습니다.
