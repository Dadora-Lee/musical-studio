현재 UI 상태

기능 상태 메모
Number 선택 구현 현재는 모든 Member가 모든 Number에 접근 가능합니다.
NickName 선택 구현 로그인 전 test 용도입니다. 선택해도 Number 목록은 필터링하지 않습니다.
MusicXML A4 렌더링 구현 OSMD title은 숨겼고, A4 한 페이지에 12~16마디 수준을 목표로 조정했습니다.
MR/AR 재생 1차 구현 HTMLAudio 기반으로 재생, 정지, 10초 이동, seek slider를 붙였습니다. AR 진행 색상 동기화는 추가 점검 대상입니다.
Recording prototype MediaRecorder 기반 골격과 WAV 변환 흐름이 있습니다. 파형, sync 정밀도, 제출 저장은 다음 단계입니다.
Feedback/Comment 구현 제출된 take를 클릭하면 우측에 코멘트가 표시됩니다.

남은 이슈와 반복 루프

우선순위 이슈 해결 방향 검증 기준
1 MR/AR Track thumb 원형 UI 제거 slider thumb를 숨기고, 현재 위치를 세로 선으로만 표시합니다. 트랙에는 선만 보이고 동그라미 handle이 보이지 않아야 합니다.
2 AR 진행 구간 색상 미반영 source 전환 후 active track progress 계산이 AR에도 동일하게 적용되는지 확인하고 수정합니다. AR 재생/seek 시 진행 구간이 MR과 같은 방식으로 채워져야 합니다.
3 선 이동 후 해당 위치에서 재생 drag/click 시 audio.currentTime 반영 후 재생 중이면 그 위치에서 계속 재생되게 보장합니다. seek 후 재생 버튼 또는 재생 중 seek 모두 선택 위치에서 소리가 나와야 합니다.
4 실제 총 재생 시간 표시 metadata 로드 후 실제 duration을 우선 표시하고, 로드 전에는 DB durationLabel을 fallback으로 표시합니다. MR/AR 각각 실제 metadata 기준의 총 분:초가 표시되어야 합니다.
1. 리스트업현재 미구현/불편/버그를 표로 적습니다.
2. 원인 확인재현 경로, 상태값, DOM, 오디오 metadata를 확인합니다.
3. 해결가장 작은 단위로 테스트와 구현을 추가합니다.
4. 검증unit, typecheck, browser smoke를 실행합니다.
5. 재리스트업남은 항목을 다시 갱신하고 다음 루프로 이동합니다.

운영 규칙: 사용자에게 보이는 UI를 바꿀 때는 먼저 변경 전/변경 후 HTML 제안서를 만들고 승인 후 구현합니다. 단, 이미 승인된 항목의 버그 수정은 동일 범위 안에서 진행하고 검증 결과를 남깁니다.
