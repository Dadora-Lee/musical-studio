작성일: 2026-05-31 · 대상 화면 http://localhost:3000/work · 대상 컴포넌트 ScoreViewer

구현 전 기록

전제

사용자는 B형 균등 연습형을 선택했다. 이번 구현은 주요 UI 위치를 유지하면서 중앙 MusicXML 렌더링의 연습 가독성, MR/AR seek, Recording 흐름을 안정화하는 범위로 진행한다.

변경 전

  • OSMD compact 렌더링과 A4 frame fit은 적용되어 있다.
  • RenderXMeasuresPerLineAkaSystem = 4 의도는 있으나 B형 적용 상태를 DOM/검증 문서에서 명시적으로 식별하기 어렵다.
  • 마디 간격이 실제 화면에서 얼마나 균등한지 Playwright 측정 결과가 별도 문서로 남아 있지 않다.
  • MR/AR와 Recording 흐름은 기본 동작이 있으나 다음 작업에서 동일 조작 품질을 다시 검증해야 한다.

중앙 MusicXML
제출/Feedback 유지

변경 후

  • B형 균등 연습형을 실제 MusicXML 렌더링 기준으로 식별 가능하게 만든다.
  • 목표는 한 줄 4마디, A4 한 페이지당 12~16마디, MusicXML title 유지, A4 안에서 잘리지 않는 fit이다.
  • 원본 MusicXML의 print, new-system, new-page 기반 줄바꿈은 prototype 연습 레이아웃에서는 계속 제거한다.
  • OSMD가 완전 동일 마디 폭을 보장하지 못하는 부분은 Playwright 측정 결과로 기록한다.

유지되는 UI 위치

좌측Number 목록은 모든 member가 접근 가능한 목록으로 유지한다.
상단HeaderLayout의 NickName 선택은 테스트용 selector로 유지한다.
중앙MusicXML A4 viewer와 page navigation 위치를 유지한다.
하단MR/AR/악보재생 transport와 Recording lane 위치를 유지한다.
우측제출 상태, Take 목록, 제출된 recording 클릭 시 Feedback 표시 구조를 유지한다.

검증 기준

  • /work에서 MusicXML SVG가 렌더링된다.
  • MusicXML title이 사라지지 않는다.
  • active page가 A4 frame 안에서 잘리지 않는다.
  • 한 줄 4마디, 페이지당 12~16마디 목표가 코드와 측정 문서에 남는다.
  • MR/AR slider drag seek, 재생, 정지, 일시정지, 10초 이동이 일관된다.
  • Recording start/pause/resume/stop/save 흐름이 prototype으로 끊기지 않는다.
  • Feedback 기준은 v1 take 전체, v1.5 timestamp, v2 마디+시간 위치로 문서화한다.

되돌릴 기준

  • A4 영역에서 악보가 잘리거나 제목이 사라지면 되돌린다.
  • 좌측 Number 목록, 상단 NickName, 하단 Transport/Recording, 우측 제출/Feedback 위치가 이동되면 되돌린다.
  • MR/AR seek 후 play() request was interrupted 로그가 다시 발생하면 수정 루프를 반복한다.
  • DB schema, migration, 실제 MusicXML/MR/AR 파일이 변경 대상으로 들어오면 제외한다.

진행 메모

이 문서는 B형 실제 적용을 위한 변경 전/후 기록이다. 이미 B형 방향은 승인되었으므로, 구현 중 UI 주요 위치를 이동하지 않는 범위에서 진행한다.
