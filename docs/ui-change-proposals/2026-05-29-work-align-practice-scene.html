승인용 UI 변경 제안서

/work 화면을 practice-studio-scene.html 기준으로 정렬

이 문서는 구현 전에 확인하는 변경 전/후 제안서입니다. 승인 전에는 기존 `/work` 화면의 배치, 컴포넌트 위치, 사용자-facing 문구를 변경하지 않습니다.

구현 범위가 아니라 승인 범위입니다. 사용자가 승인하면 아래 범위 안에서만 UI를 수정합니다.

1. 핵심 판단

현재 `/work`는 기능 구현 중심으로 확장되면서 `practice-studio-scene.html`의 앱형 레이아웃과 다르게 보입니다. 사용자가 원한 기준은 HTML 시안의 구조이므로, 기능은 유지하고 화면 골격만 시안에 맞춰 되돌리는 방향을 제안합니다.

1-1. 확정 구현 기준

항목 확정 방향
시안 반영 수준 `practice-studio-scene.html`의 레이아웃, 색상, 간격, 컴포넌트 밀도를 거의 그대로 맞춥니다. 단, 기존 기능 동작을 깨뜨리는 시각 요소는 기능 안정성을 우선합니다.
A4 MusicXML Viewer 중앙 영역 안에서 A4 비율을 유지합니다. 악보는 세로 스크롤로 보고, 페이지 사이의 여백은 고정해서 흔들리거나 동적으로 튀지 않게 합니다.
Transport / Recording MR/AR/악보재생, 아이콘 버튼, MRTracker, Recording 트랙, 볼륨 조절은 하단 transport 안에 유지합니다. 장치 선택은 이번 골격 변경에서는 접힘 패널 또는 추후 설정값으로 분리합니다.
Feedback / Comment 우측 패널에서 제출된 recording을 클릭했을 때 해당 recording의 Feedback/Comment가 보이도록 합니다. 기본 상태에서는 recording 목록을 우선 보여줍니다.
이번 단계의 목표 먼저 `/work`의 골격과 레이아웃을 시안 기준으로 정렬합니다. 세부 기능 추가나 DB/Supabase 연동은 이 정렬이 끝난 뒤 다시 별도 단계로 진행합니다.

2. 변경 전 / 변경 후 와이어프레임

변경 전: 현재 /work 카드형 확장 화면
변경 후: practice-studio-scene.html 기반 앱형 화면

3. 컴포넌트별 변경 내용

영역 현재 상태 변경 후 제안 보존 조건
HeaderLayout 상단 설명/상태 정보가 비교적 크게 보이는 형태 시안처럼 56px 정도의 얇은 topbar로 정리합니다. 우측에는 테스트용 Member NickName 콤보박스를 유지합니다. Member 선택 유지
Number List 카드형 버튼과 넓은 행 높이 `practice-studio-scene.html`처럼 엑셀/파일 리스트에 가까운 compact row로 변경합니다. 선택된 넘버는 좌측 컬러 라인과 배경으로 표시합니다. 좌측 목록 삭제 금지
MusicXML Viewer A4 악보는 들어갔지만 주변 레이아웃이 시안과 다름 가운데 workspace 안에 A4 용지 프레임을 고정합니다. 악보 자체는 기존 OSMD/MusicXML 로딩 방식을 유지합니다. 실제 MusicXML 유지
Transport MR/AR/악보재생 기능과 녹음 UI가 기능 중심으로 배치됨 우측 아이콘 버튼 묶음, MRTracker, Recording 트랙을 시안 하단 transport 패널 안에 정렬합니다. MR/AR/악보재생 유지
Right Panel 녹음/제출/Feedback 카드들이 현재 스타일로 존재 시안의 `.side` 영역처럼 제출 상태, Take 목록, Feedback 패널을 세로로 유지합니다. 제출 목록 클릭 시 Comment/Feedback을 보는 흐름은 유지합니다. Feedback 접근 유지
추가 Content 마감일, 상태, 장치 선택 등 추가 여지가 있음 이번 변경에는 새 content를 추가하지 않습니다. 마감 날짜 등록 같은 새 컴포넌트는 별도 변경 전/후 제안서를 만든 뒤 진행합니다. 추가 기능 보류

4. 구현 시 지켜야 할 범위

  • 기능 로직은 가능한 유지하고, 레이아웃과 시각 구조만 시안 기준으로 맞춥니다.
  • 좌측 곡 리스트, 중앙 악보, 하단 transport, 우측 제출/Feedback 흐름을 제거하지 않습니다.
  • MusicXML은 기존 `src/lib/musicxml/` 경로의 로딩/파싱 흐름을 유지합니다.
  • MR/AR 파일 라우트, 녹음, WAV 변환, Take 생성 흐름은 이번 제안의 변경 대상이 아닙니다.
  • Supabase, DB schema, 인증/로그인 전환은 이번 제안 범위에서 제외합니다.

5. 승인 후 검증 기준

검증 항목 성공 기준
화면 구조 좌측 Number List, 중앙 A4 악보, 하단 Transport, 우측 Feedback 패널이 한 화면에 유지됩니다.
악보 가시성 A4 프레임이 흔들리지 않고, MusicXML 로딩 후 페이지형 악보가 안정적으로 보입니다.
오디오 조작 MR/AR/악보재생 선택과 10초 전/재생/일시정지/정지/10초 후 아이콘 버튼이 유지됩니다.
테스트 `pnpm lint`, `pnpm typecheck`, `pnpm test`를 통과하고 `/work`에서 브라우저 확인을 진행합니다.

6. 승인 요청

이 제안이 맞다면 다음 단계에서 위 범위 안에서만 `/work` UI를 `practice-studio-scene.html` 기반으로 정렬합니다. 범위 밖의 새 기능이나 새 content는 별도 제안서로 분리합니다.
