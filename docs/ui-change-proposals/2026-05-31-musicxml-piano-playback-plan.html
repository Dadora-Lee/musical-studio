최종 검토 반영

목표

현재 소리 없는 악보재생을 실제 MusicXML note event 기반 피아노 연주 prototype으로 전환한다. Tone.js로 피아노 계열 synth를 재생하고 현재 연주 위치를 OSMD cursor/page와 동기화한다.

기술 선택

  • Tone.js: 이미 dependency에 있으므로 새 dependency 없이 사용한다.
  • OSMD: 기존 MusicXML 렌더링과 cursor 표시를 유지한다.
  • src/lib/musicxml: MusicXML 파싱 단일 진입점으로 확장한다.
  • src/lib/audio-engine: Tone.js wrapper를 분리한다.

이번 단계에서 제외

  • 새 npm dependency 추가 없음
  • 실제 MusicXML/MR/AR 파일 git 추가 없음
  • DB schema, Supabase migration 변경 없음
  • 고품질 piano sample pack은 후속 승인 후 검토

최종 재검토 결과

  • 계획은 진행해도 된다. 핵심 구조는 MusicXML parser → Tone player wrapper → Practice transport → OSMD cursor sync 순서가 맞다.
  • 테스트 파일 위치는 tests/unit/lib/musicxml/playback-events.test.ts로 고정한다.
  • 1차 기본값은 전체 간단 재생이다. 모든 part를 병합하되 polyphony cap과 max event guard를 둔다.
  • source, number, MusicXML raw string이 바뀌면 기존 Tone object와 scheduler를 반드시 dispose()한다.
  • 자동 검증은 실제 소리 자체가 아니라 scheduling, player state, current time 증가, seek 결과로 판단한다. 실제 소리는 수동 청음으로 확인한다.
  • UI label이나 버튼 배치가 보이게 바뀌면 구현 전 변경 전/후 HTML 승인 문서를 먼저 작성한다.

Acceptance Criteria

  • /work에 피아노 연주 source가 표시된다.
  • MusicXML에서 추출한 note event가 Tone.js로 scheduling된다.
  • 브라우저 수동 확인에서 피아노 계열 소리가 난다.
  • play, pause, stop, 10초 이동, slider seek가 동작한다.
  • 현재 연주 위치에 따라 ScoreViewer cursor/page가 이동한다.
  • 기존 MR/AR playback과 Recording 흐름이 깨지지 않는다.
  • pnpm lint, pnpm typecheck, pnpm test가 통과한다.
