요청구현 결과
악보가 움직이지 않고 현재 위치만 표시피아노 재생/seek에서 기존 goToMeasure 호출을 제거하고 highlightMeasure를 사용하도록 변경했다. 이 API는 페이지 reveal/scroll을 하지 않고 OSMD cursor만 현재 마디 위치로 이동시킨다.
가시성 향상용 마디 렌더링 선택악보 pager에 가사 크게, 균형, 전체 라디오를 추가했다. 각각 3/4/5마디 per system 기준으로 OSMD를 다시 렌더링한다.
트랙별 볼륨/소리 토글MR/AR/Piano active lane과 Recording lane 왼쪽에 소리 활성/비활성 토글, 볼륨 슬라이더, % 표시를 배치했다. MR/AR/Piano는 source별로 볼륨과 mute 상태를 따로 기억한다.
재생 상태 표시재생/일시정지를 하나의 primary 버튼으로 합쳤고, 재생 중에는 active 스타일과 pause 아이콘으로 바뀐다.

2차 계획 검토 결과

검토 결과 A안 구현 방향은 유지한다. 다만 “개별 음악과 녹음한 것을 같이 들을 수 있다”는 의도에 맞춰, 선택된 source 하나의 볼륨 상태를 공유하지 않고 MR/AR/Piano별 볼륨과 mute 상태를 분리했다.

Recording lane은 현재 POC에서 녹음 진행/monitor 기준 UI로 두고, 저장된 take와 MR/AR을 동시에 playback하는 mixer는 다음 단계의 명확한 기능 단위로 분리한다.

흔들림 관련 확인

악보가 계속 흔들릴 수 있었던 주 원인은 피아노 재생 중 현재 마디를 맞추기 위해 goToMeasure가 호출되고, 내부에서 revealCursor()가 페이지 표시와 scrollIntoView()를 실행하던 구조였다.

이번 변경에서는 피아노 재생과 seek가 highlightMeasure()만 호출하도록 분리했다. 따라서 재생 중 자동 페이지 이동은 기본 동작에서 빠졌다. 단, 사용자가 악보 렌더링 라디오를 바꾸는 순간은 의도적으로 OSMD를 다시 렌더링한다.
