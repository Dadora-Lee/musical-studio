Recording 안정화 변경 전/후 검토

작성일: 2026-06-01 · 대상 화면: /work · 대상 브랜치: codex/local-db-prototype

검토 목적

이번 변경은 기존 레이아웃을 유지하면서 Recording POC의 실제 사용 흐름을 안정화하는 작업입니다. 사용자가 MR/AR/Piano 중 하나를 기준으로 녹음하고, 결과를 local take로 저장한 뒤 다시 재생할 수 있게 만드는 것이 목표입니다.

기존 배치 유지DB 변경 없음Supabase 제외Recording 동기화 보강

변경 전

  • 하단 Transport 영역에 MR/AR/Piano 선택, 재생, 정지, seek, 녹음 버튼이 존재합니다.
  • Recording lane과 볼륨 UI가 존재하지만, 녹음 흐름의 상태 모델은 checking, idle, recording, paused, ready, unsupported, error 중심입니다.
  • 녹음 시작은 주로 MR/AR audio element와 함께 동작하며, Piano source까지 동일한 녹음 동기화 대상으로 보기에는 부족합니다.
  • 녹음 일시정지/재개도 MR/AR audio 기준 처리가 강하고, Piano player pause/resume 처리는 보강이 필요합니다.
  • local take 저장은 가능하지만, 저장된 take 선택/재생/cleanup/권한 실패 시나리오 검증을 더 명확히 해야 합니다.

변경 후

  • Recording 상태 모델을 목표 상태에 맞게 명확히 정리합니다.
  • 녹음 시작 시 현재 선택된 MR/AR/Piano source가 함께 시작됩니다.
  • 녹음 일시정지 시 현재 source도 함께 멈춥니다.
  • 녹음 재개 시 현재 source가 같은 흐름으로 이어집니다.
  • 녹음 정지 후 local take 저장 대기 상태가 명확히 보입니다.
  • 저장된 take는 우측 목록에서 선택하고 재생할 수 있습니다.
  • microphone permission 실패와 object URL/MediaStream cleanup을 테스트로 검증합니다.

유지되는 화면 구조

영역변경 여부설명
좌측 Number 목록유지곡 선택 위치와 목록 접근 방식은 변경하지 않습니다.
상단 HeaderLayout / NickName 선택유지테스트용 NickName 선택 콤보박스는 그대로 둡니다.
중앙 MusicXML유지악보 렌더링, 페이지, 마디 렌더링 옵션은 이번 작업에서 구조 변경하지 않습니다.
하단 Transport / Recording동작 보강위치는 유지하고 Recording 상태/동기화/저장 흐름만 안정화합니다.
우측 submitted take / Feedback연결 보강위치는 유지하고 저장된 local take를 선택/재생할 수 있게 흐름을 명확히 합니다.

되돌릴 기준

  • 좌측 Number 목록, 중앙 MusicXML, 하단 Transport, 우측 Feedback 배치가 바뀌면 되돌립니다.
  • MR/AR/Piano 기존 재생/seek가 퇴행하면 되돌립니다.
  • 녹음 실패 시 사용자가 다음 행동을 알 수 없는 상태가 되면 되돌립니다.
  • DB/Supabase/Auth/RLS 변경이 발생하면 이번 작업 범위 밖이므로 되돌립니다.
