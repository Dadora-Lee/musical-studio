Recording 안정화 구현 결과

작성일: 2026-06-01 · 대상 화면: /work · 브랜치: codex/local-db-prototype

구현 요약

기존 화면 배치를 유지하면서 Recording POC의 상태 전환과 playback source 동기화를 보강했습니다.

좌측 Number 목록 유지 중앙 MusicXML 유지 하단 Transport/Recording 유지 우측 Take/Feedback 유지

반영 내용

  • Recording 상태 모델에 requesting-permission, stopping, ready-to-save, saving, saved 흐름을 추가했습니다.
  • 녹음 시작 시 현재 선택된 MR/AR/Piano source가 함께 시작되도록 보강했습니다.
  • 녹음 일시정지/재개 시 Piano source도 MR/AR과 동일하게 멈추고 이어지도록 수정했습니다.
  • 일시정지 중에는 새 녹음 시작 버튼이 활성화되지 않도록 상태 조건을 정리했습니다.
  • Recording lane 진행 시간이 pause 구간을 불필요하게 포함하지 않도록 누적 시간 기준을 분리했습니다.
  • 저장된 local take의 object URL을 컴포넌트 unmount 시 revoke하도록 cleanup을 추가했습니다.
  • microphone permission 실패 시 사용자에게 실패 메시지를 표시하는 테스트를 보강했습니다.
  • Chromium E2E에서 녹음 시작/일시정지/재개/정지/저장 흐름을 검증했습니다.

남은 제한사항

  • 이번 작업은 local object URL 기반 POC이며 Supabase Storage 업로드는 포함하지 않았습니다.
  • DB schema, Auth/RLS, migration은 변경하지 않았습니다.
  • waveform 정밀 분석과 마디 단위 feedback 연결은 다음 단계 범위입니다.
  • 실제 녹음 파일의 sync truth는 장기적으로 WAV이지만, 이번 구현은 브라우저 지원 차이를 고려해 fallback WAV 생성을 유지합니다.
  • WebKit 검증은 이번 필수 범위가 아니며 Chromium 기준으로 확인했습니다.

다음 추천 작업

  • 저장된 take의 제출 버튼과 Feedback 선택 상태 연결
  • MR/AR/Piano/Recording mixer를 실제 simultaneous playback 기준으로 분리
  • Recording waveform 또는 간단한 amplitude lane 표시
  • Supabase Storage recordings bucket 업로드 설계와 migration 문서화
