Prototype 환경 적용 및 DB 마이그레이션 지침

이 문서는 현재 Musical Studio prototype을 다른 WSL/개발 환경에서 실행하고, local DB schema를 Supabase 환경으로 옮길 때 확인해야 할 절차를 정리합니다. 실제 MusicXML/MR/AR 파일은 저작권 및 용량 문제로 git에 넣지 않고 외부 저장소 또는 로컬 경로로 연결합니다.

1. 환경 전제

항목 현재 기준 다른 환경 적용 방법
Node / pnpm /home/jieun/.nvm/versions/node/v22.22.3/bin 하위 Node와 pnpm 사용 동일 major Node를 설치하고 pnpm install을 실행합니다.
WSL Repo /home/jieun/projects/musical-studio Windows 복사본이 아니라 WSL checkout을 source of truth로 사용합니다.
Prototype Assets /mnt/e/04.Musical/08.팬레터/01.넘버 같은 경로를 mount하거나, src/lib/musicxml/prototype-source.server.ts의 path를 환경에 맞게 조정합니다.
Secrets 커밋 금지 .env*, .env/, credential JSON, key 파일은 git에 넣지 않습니다.

2. 실행 절차

Local App

Next 개발 서버

cd /home/jieun/projects/musical-studio
export PATH=/home/jieun/.nvm/versions/node/v22.22.3/bin:/home/jieun/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

브라우저는 http://localhost:3000/work를 권장합니다. 127.0.0.1에서는 HMR websocket이 불안정할 수 있습니다.

임시 prototype에서는 서버 route가 로컬 파일을 읽습니다. 운영 환경에서는 이 부분을 Supabase Storage public/signed URL 또는 Google Drive read-only URL로 대체해야 합니다.

4. DB Schema 마이그레이션

Table 주요 컬럼 용도
numbers title, musicxml_url, ar_url, mr_url, vocal_url 뮤지컬 Number와 외부 asset URL을 저장합니다.
members nickname, member_type, castings 배우/연출/guest와 casting 정보를 prototype 수준으로 관리합니다.
works number_id, member_id, casting_name, file_name, file_url 사용자 녹음 제출물을 저장합니다.
comments work_id, member_id, text 제출된 work에 대한 Feedback/Comment를 저장합니다.

5. Supabase로 옮길 때 절차

순서 작업 주의점
1 supabase/migrations/20260527000000_initial_schema.sql을 리뷰합니다. Auth/RLS policy는 아직 prototype 범위 밖입니다. 실제 배포 전 별도 ADR이 필요합니다.
2 Supabase project에 migration을 적용합니다. 자동 실행하지 말고 사람이 Supabase CLI 또는 Dashboard에서 실행합니다.
3 supabase/seed.sql로 prototype row를 입력합니다. 실제 asset URL은 Storage/Drive URL로 치환합니다.
4 recordings bucket을 확인합니다. 녹음 원본은 WAV가 sync truth이며, bucket은 recordings입니다.
5 앱의 데이터 소스를 fixture에서 Supabase query로 전환합니다. practiceStudioPrototype는 UI prototype 검증용으로 유지하거나 test fixture로 이동합니다.

6. 다른 환경에서 꼭 바꿀 값

대상 현재 변경 방법
MusicXML/MR/AR 파일 경로 /mnt/e/04.Musical/08.팬레터/01.넘버/... prototype-source.server.ts의 map을 환경별 source로 바꿉니다.
Supabase URL/key 커밋되지 않음 .env.local 또는 .env/ 하위 로컬 파일로만 관리합니다.
실제 Member/Auth NickName select Google OAuth 이후 로그인 사용자와 members row를 연결합니다.

마이그레이션 원칙: prototype schema는 가볍게 유지합니다. 인증, RLS, Storage policy, 역할 권한이 들어가는 순간에는 DB 변경으로 간주하고, 실행 전에 별도 검토와 사용자 승인을 받아야 합니다.
