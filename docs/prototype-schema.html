Musical Studio

Prototype Data Schema

Practice Studio 프로토타입을 빠르게 검증하기 위한 단순 스키마입니다. 배역 캐스팅은 members.castings 배열에 보관하고, MusicXML Part 이름과 매칭합니다.

Prototype first · normalize later

numbers

  • id int primary key
  • title Number 이름
  • musicxml_url 악보 MusicXML
  • ar_url AR audio
  • mr_url MR audio
  • vocal_url MR 제거 Vocal reference

members

  • id int primary key
  • nickname 화면 표시 이름, prototype key
  • member_type player | direction | guest
  • castings text[]: Hikaru, Ensemble 등

works

  • id int primary key
  • number_id numbers.id
  • member_id members.id
  • casting_name 제출 당시 배역명
  • file_name take_03.wav
  • file_url recording storage URL
  • created_at 제출/생성 시각

comments

  • id int primary key
  • work_id works.id
  • member_id 작성자 members.id
  • text 피드백 본문
  • created_at 작성 시각

데이터 흐름

1. Number 등록 MusicXML, AR, MR, Vocal 파일을 Number에 연결합니다.
2. Part 추출 MusicXML에서 Hikaru, Ensemble 같은 Part 이름을 읽습니다.
3. Member 매칭 members.castings가 MusicXML Part 이름과 맞으면 연습 대상으로 봅니다.
4. Work 생성 Member가 Number를 녹음/제출하면 Work가 만들어집니다.
5. Comment 작성 Direction 또는 Member가 제출된 Work에 피드백을 남깁니다.

Prototype 예시

const member = {
  id: 1,
  nickname: "tani",
  member_type: "player",
  castings: ["Hikaru", "Ensemble"]
};

const number = {
  id: 10,
  title: "빛나는 밤의 약속",
  musicxml_url: "/storage/numbers/duet.musicxml",
  ar_url: "/storage/numbers/duet-ar.mp3",
  mr_url: "/storage/numbers/duet-mr.mp3",
  vocal_url: "/storage/numbers/duet-vocal.wav"
};

const work = {
  id: 100,
  number_id: 10,
  member_id: 1,
  casting_name: "Hikaru",
  file_name: "take_03.wav",
  file_url: "/storage/recordings/1/take_03.wav",
  created_at: "2026-05-29T00:10:00+09:00"
};

const comment = {
  id: 1000,
  work_id: 100,
  member_id: 2,
  text: "00:42 진입 박자가 MR보다 조금 늦어요.",
  created_at: "2026-05-29T00:20:00+09:00"
};

현재 결정

guest 사용

최소 기능 사용자 타입은 none 대신 guest로 표현합니다.

캐스팅은 members.castings

Prototype에서는 별도 roles/castings 테이블을 만들지 않고 배열로 보관합니다.

MusicXML Part와 이름 매칭

MusicXML에서 추출한 Part 이름과 members.castings 값을 비교합니다.

나중에 정규화

더블캐스팅, 공연별 배역 관리, 권한이 복잡해지면 roles/member_castings 테이블로 분리합니다.
