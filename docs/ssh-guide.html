🔐 SSH 워크플로 가이드

공동 개발자가 dev 서버에 SSH로 접근해서 작업하는 방법.

아키텍처

[Collaborator PC]
  ssh -p 2222 soswolf@musicalstudio.freedynamicdns.net
                                  ↓ (인터넷, 공유기 2222 forwarding)
[Owner Windows PC]
  └── WSL2 Ubuntu 24.04
       ├── sshd :2222              ← SSH 서버
       ├── pnpm dev :3000          ← Next.js dev server
       └── ~/projects/musical-studio

1. Owner 측 1회 셋업 Owner

WSL 안에서 sudo-bootstrap 실행

cd ~/projects/musical-studio
bash scripts/sudo-bootstrap.sh

이 스크립트가 자동 수행:

  • sudoers NOPASSWD 룰 추가 (apt-get, service, mkcert 등)
  • openssh-server 설치
  • /etc/ssh/sshd_config.d/musical-studio.conf 작성 (port 2222, 키 only)
  • Playwright deps + mkcert + libnss3-tools 설치
  • GitHub SSH key import (ssh-import-id gh:Dadora-Lee)
  • WSL boot시 SSH 자동 시작 설정

Windows 측 Firewall + Port Forwarding

관리자 권한 PowerShell:

New-NetFirewallRule -DisplayName "WSL SSH 2222" `
  -Direction Inbound -Protocol TCP -LocalPort 2222 -Action Allow

공유기 admin에 포트포워딩 추가:

  • 외부 포트: 2222 (TCP)
  • 내부 IP: 192.168.31.101 (= HOST_LAN_IP)
  • 내부 포트: 2222

파트너 GitHub key import (파트너 합류 시)

ssh-import-id gh:<partner-github-username>

파트너의 github.com/<username>.keys 에 등록된 SSH 공개키가 ~/.ssh/authorized_keys에 자동 추가됨.

2. Collaborator 측 접속 Partner

사전 준비: SSH key를 GitHub에 등록

본인 PC에서:

ssh-keygen -t ed25519 -C "you@example.com"          # 없으면 생성
cat ~/.ssh/id_ed25519.pub                            # 출력 복사
# github.com → Settings → SSH and GPG keys → New SSH key → 붙여넣기

등록 확인: curl https://github.com/<username>.keys 에서 본인 공개키 보이면 OK.

접속

# 같은 LAN
ssh -p 2222 soswolf@192.168.31.101

# 인터넷 (다른 LAN)
ssh -p 2222 soswolf@musicalstudio.freedynamicdns.net

최초 접속 시 fingerprint 확인 prompt 나오면 yes.

접속 후 일반 워크플로

# 최신 main 받기
cd ~/projects/musical-studio
git pull origin main

# 새 브랜치
git worktree add -b ai/codex/my-feature ../musical-studio-my-feature main
cd ../musical-studio-my-feature

# 작업 + 커밋 + push (gh credential helper 통해 자동 인증)
git add <files>
git commit -m "feat: ..."
git push -u origin ai/codex/my-feature

# Draft PR 생성
gh pr create --draft --title "..." --body "..."

3. VSCode Remote SSH (편의)

설치

VSCode → Extensions → "Remote - SSH" 검색 → Install.

접속

Cmd/Ctrl+Shift+P → "Remote-SSH: Connect to Host" → "Add New SSH Host" →

ssh -p 2222 soswolf@musicalstudio.freedynamicdns.net

접속 후 File → Open Folder → /home/soswolf/projects/musical-studio

이제 VSCode 안에서 원격 파일 직접 편집 + 터미널 사용 가능. Native 같은 경험.

4. dev server 재시작 / 로그 보기 Owner/Partner

dev server 시작 (background)

cd ~/projects/musical-studio
nohup pnpm dev --hostname 0.0.0.0 > /tmp/dev.log 2>&1 &
disown
echo "PID: $!"

로그 보기

tail -f /tmp/dev.log

중지

pkill -f "next dev"
pkill -f "next-server"

5. 트러블슈팅

접속 거부 (Connection refused)

  1. Owner 측 WSL이 켜져있는지 (wsl --list -v로 Running 상태)
  2. SSH 서비스 동작 중인지 (Owner: sudo service ssh status)
  3. Windows Firewall 룰 있는지 (관리자 PowerShell: Get-NetFirewallRule -DisplayName "WSL SSH 2222")
  4. 공유기 포트포워딩 활성화됐는지

Permission denied (publickey)

  1. 본인 SSH 공개키가 GitHub에 등록되어 있는지 (curl https://github.com/<you>.keys)
  2. Owner가 본인 username을 import했는지 (Owner: ssh-import-id gh:<you>)
  3. ~/.ssh 권한이 700인지 (본인 PC: chmod 700 ~/.ssh; chmod 600 ~/.ssh/id_*)

DDNS IP 변경됨

공유기 DDNS 클라이언트가 자동 갱신 안 됐을 가능성. 새 IP 확인:

# Owner WSL에서
curl -s ifconfig.me/ip

freedynamicdns.net 사이트에서 수동 갱신 또는 공유기 DDNS 재인증.

6. 보안 룰

SSH 설정:
  • Password 인증 비활성화 (키 only)
  • Root 로그인 금지
  • AllowUsers soswolf (다른 계정 차단)
  • 포트 2222 (default 22 회피)
파트너 이탈 시:
  1. Owner WSL: ~/.ssh/authorized_keys에서 해당 키 제거
  2. GitHub collaborator 제거 (gh api --method DELETE /repos/Dadora-Lee/musical-studio/collaborators/<username>)
  3. Google Test users에서 제거
  4. (필요시) Secret 회전
